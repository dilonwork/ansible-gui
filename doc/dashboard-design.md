# 儀表板設計（Dashboard Design）v1

> 設計稿：`doc/mockups/dashboard.html`（可直接用瀏覽器開啟）＋ `doc/mockups/dashboard.png`
> 數字皆為示意。桌面版優先（維運工具主要使用場景），深色主題。

![儀表板設計稿 v1](mockups/dashboard.png)

## 設計目標

維運人員打開第一眼就要回答三個問題：

1. **現在有沒有壞東西？** → 叢集健康、NotReady 節點、失敗任務
2. **接下來要做什麼？** → 待辦維運（待升級、待 patch、下次排程）
3. **正在發生的事？** → 進行中任務即時日誌

## 版面結構

```
┌──────┬───────────────────────────────────────────┐
│ 側邊 │ 頂欄：叢集切換 / 搜尋 / 通知 / 使用者      │
│ 導航 ├───────────────────────────────────────────┤
│      │ KPI 卡 ×5（主機 / 叢集 / 待升級 / 進行中 / 成功率）│
│      ├──────────────────────────────┬────────────┤
│      │ 叢集健康卡                   │ 進行中任務 │
│      │ Worker 節點表（核心）         │ （即時日誌）│
│      │ 最近任務                     │ 待辦維運   │
│      │                              │ 快速動作   │
└──────┴──────────────────────────────┴────────────┘
```

## 關鍵設計決策

### 1. Worker 節點表是第一屏的核心

本專案的差異化就是「K8s 節點的 OS 層維運」，所以節點表直接放在第一屏中央，而不是藏在二級頁面。欄位經過取捨：

- 保留：主機名、角色、K8s 版本、kubelet 版本、CPU/記憶體、狀態、操作
- 捨去（放節點詳情頁）：labels/taints 全量、磁碟、網路、Events

**版本漂移**用琥珀色 badge 獨立標示（不是混在 Ready 裡），因為它是觸發升級工作流的入口；該列的操作按鈕直接變成「升級」。

### 2. 狀態色階只有四種

- 綠：正常（Ready、成功）
- 琥珀：需要注意但不緊急（版本漂移、待 patch）
- 紅：壞了（NotReady、失敗）
- 藍：進行中（任務執行中、排程）

維運儀表板最忌顏色氾濫，四色走天下。

### 3. 右欄是「行動區」

- **進行中任務**：即時日誌只顯示最後 ~6 行，完整版點「即時日誌 →」進任務詳情頁
- **待辦維運**：每條都是一個可點擊的行動（點「3 節點版本漂移」→ 跳到已預選這 3 台的節點維護頁）
- **快速動作**：2×2 按鈕，新增主機 / 建立任務 / 節點維護 / 新增排程

### 4. 叢集切換在頂欄

多叢集是 P1，但頂欄的叢集選擇器現在就留好位置；切換後 KPI 與節點表跟著過濾（或選「全部叢集」看彙總）。

## 之後要細化的頁面（v2 設計稿）

1. **節點維護頁**：一鍵工作流的步驟條（cordon → drain → patch → 驗證 → uncordon）＋ 每台即時進度 ＋ 暫停/恢復
2. **任務詳情頁**：全量即時日誌 ＋ 主機維度成功/失敗矩陣 ＋ 重跑失敗節點
3. **節點詳情抽屜**：從表格點主機名滑出，含完整 labels、系統資訊、最近任務歷史
4. 手機版：只保留 KPI ＋ 異常告警 ＋ 審批（on-call 在外只處理這三件事）
